| 2026-10-28 | Backend tests live in `backend/tests/`, not a root `tests/`. | Keeps pytest, ruff and mypy in the backend's own uv project; `scripts/check.sh` runs them there. |
| 2026-10-28 | Backend routes have no `/api` prefix (plan section 6); the Vite dev server proxies `/api/*` to the backend and strips the prefix. | The frontend calls same-origin `/api/...`, so no CORS setup is needed. |
| 2026-10-28 | `make test` will call `./scripts/check.sh` (ruff, mypy, pytest, oxlint, tsc, vitest). | One definition of done for people, agents and CI. |
| 2026-10-28 | Scope for a 3–4 day time box: M0–M6 with the template provider fully working, then M7 in template mode. Calibration (M8) and Docker are cut first. | The core story is replay, risk, playbook findings, human approval; everything must run offline. |
| 2026-10-28 | A gap is an open finding; an action is the remedy proposed for it. The decision package merges "Playbook actions" and "Gaps" into one list of gaps with proposed actions. | No field in the data separates the two; the demo contract calls open findings gaps. |
| 2026-10-28 | Approval counts the action as done from that moment (it sets the rule's state). The UI and `assumptions_limitations.md` say so. | No field feedback exists in the prototype; the demo path needs a single step. |
| 2026-10-28 | No auth: a role selector in the header, recorded as `decided_by`. The backend accepts conflict decisions only from the Incident Commander; below Full activation the Director holds that role. | Shows "IC decides" as an enforced rule without building authentication. |
| 2026-10-28 | Activation level is derived from hours to landfall with `(to_hours, from_hours]` bounds (72 h → prepare, 48 h → full). Deadlines run on scenario time: `hours_since_full_activation = 48 − hours_to_landfall`, overdue when > 12. Audit events store scenario and wall-clock time. | The YAML bounds overlap at 72 and 48; this choice reproduces section 8. |
| 2026-10-28 | The operator can advance with undecided items: they close as "not decided" in the audit log, state is unchanged, and the gap usually reopens at the next advisory. | The storm does not wait; keeps the demo moving. |
| 2026-10-28 | LangGraph runs the advisory cycle (see `docs/adr/0001-langgraph-for-the-advisory-cycle.md`). | Explicit, resumable human-approval interrupt. |
| 2026-10-28 | LLM providers: Anthropic and template. Azure OpenAI is a stub behind the same interface. | Time box; the interface leaves room for Azure. |
| 2026-10-28 | Prompts live in `backend/app/agent/prompts/` as versioned files (CODING_STANDARDS L3 follows the plan). | Plan section 4. |
| 2026-10-28 | Each decision resumes the advisory's LangGraph thread (`Command(resume=...)`); only the deterministic `apply_decision` node writes state and its audit event; the graph loops to `await_approval` until no items remain. Advancing resumes the old thread once with "expire" so `finalise` runs. One thread per advisory; the checkpointer has its own SQLite file, cleared by `make demo-reset`. | LangGraph owns the approval loop, so "only deterministic code writes state" is visible in the graph. |
| 2026-10-28 | Approval sets every `satisfied_if` key of the rule to true. P-4.3 sets `generators_fuelled` to the required count. Generators are not a pool (P-4.5 does not consume fuelled generators). P-4.1 is an item for Planning. P-7.1 is satisfied only by approving the situation report. `*_current` flags reset each advisory; asset state carries over. | Approval means done (see above); one mapping rule plus two named exceptions. |
| 2026-10-28 | Approve: the item's owner role, or the Incident Commander/Director. Override: only the Incident Commander/Director (an override is a deviation, P-8.1). Conflict: only the Incident Commander. | Follows P-3.x and P-8.1. |
| 2026-10-28 | Conflict outcomes: "Defer" (crews withdraw) or "Alternative measure" (free text), reason required; no "proceed" option; neither sets the blocked action's state. | P-4.7 is not waived; P-8.2: tools flag, never resolve. |
| 2026-10-28 | From M8, situation report approval moves into M6 and a plain audit list (filter by actor) into M6/M7. Only calibration is cut. | P-7.1 needs approval; the audit list proves "human approves, logged". |
| 2026-10-28 | The Incident Commander may edit the draft situation report before approving; draft and approved text are both stored; the audit event marks it edited. Citation validation runs on the draft. | CODING_STANDARDS F4: AI content is editable before use. |
| 2026-10-28 | Docker is cut: M0 and M9 are done with `make dev` (backend :8000, frontend :5173) and `make demo-reset` instead of `docker compose up`. | Time box; Docker can return at the end. |
| 2026-10-28 | Demo seeds are placed by construction relative to the scripted track; everything else is random (seed 42). `make data` runs the hazard and score code and fails loudly if a seed does not hold. | Deterministic and explainable; a physics change breaks the data visibly. The full seed check needs M3. |
| 2026-10-28 | The LLM draft is structured: sections → paragraphs with `text`, `clause_ids[]`, `asset_ids[]`. The citation validator checks the lists and that every ID in the text is listed. The template provider returns the same shape. | CODING_STANDARDS L1; citations render as chips. |
| 2026-10-28 | `make dev` reads a local `backend/.env` (gitignored; `.env.example` lists the names) with `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY`, `LLM_MODEL=claude-sonnet-5-5`; `temperature=0` for the draft. Tests always force the template provider and ignore `.env`. `LLM_PROVIDER=template make dev` runs offline. | Live demo with Claude; offline demo and tests stay possible (hard rule). |
| 2026-10-28 | Scoring runs on advance: `POST /advisories/next` computes exposure and scores for that advisory, then starts the graph. | "A new advisory arrives"; under a second for 50 members × ~200 assets. |
| 2026-10-28 | One operations screen: header (stepper, hours to landfall, activation level, role selector), map on the left, tabs on the right (Risk list, Decision package, Copilot), asset explain drawer; Audit and Data quality are separate routes; disclaimer footer. | The demo stays on one screen; stepping updates everything together. |
| 2026-10-28 | Scoring spec readings: inland decay applies while the storm centre is more than 10 km inland (Vmax × 0.85); consequence is one hop (own customers + directly dependent assets' customers + weights of directly fed facilities), each downstream entity counted once; at advisory 1 the diff reports the top 10 as "initial", with no rank moves. | Plan section 3 is ambiguous on these points. |
| 2026-10-28 | The territory stays fictional: a synthetic Gulf-style peninsula on a planar km grid (`x_km`, `y_km`, Leaflet `CRS.Simple`, no tiles) instead of real Florida. Stretch goal after M6: a separate "Historical context" panel with a real Florida outline and real past storm tracks only (public NOAA data, no assets). | Hard rule "no real places"; fictional assets at real locations would read as claims about real infrastructure. |
| 2026-10-28 | Storm parameters (landfall intensity, Rmax, forward speed, peak surge, track shift T-72 → T-24) come from real Florida landfalls, sourced in `docs/research/florida-hurricanes.md`. The scenario storm stays unnamed. | Realism from data, not from place. |
| 2026-10-28 | `LLM_PROVIDER=anthropic` without a usable key fails at startup with a message naming `ANTHROPIC_API_KEY` and the template option. A failing call during a run falls back to the template draft for that advisory, recorded as `provider: template (fallback)` in the audit event. | A silent fallback would hide the feature being demoed; one failed call must not stop the demo. |
| 2026-10-28 | The scenario storm is modelled on Ian (2022), unnamed: vmax 130, 130, 135, 140, 145 mph and peak surge 2.5, 2.5, 3.0, 3.5, 4.0 m for advisories 1–5; rmax 37 km constant; forecast landfall shifts ~40 km east at advisories 3 and 4; cone radii from NHC's 2022 table (48/72/96/124/156/185/263 km at 12–96 h). Values and sources: `docs/research/florida-hurricanes.md`. | Ian is the candidate whose forecasts shifted between advisories, matching the plan's eastward shift. |
| 2026-10-28 | The ensemble spreads the track perpendicular to its heading by `N(0, cone_radius_km)` instead of `cone_radius_km/2` (plan section 3), as a `config/scoring.yaml` value. | The NHC cone holds about two-thirds of tracks; half the radius covers only about half of it. |
| 2026-10-29 | The data generator lives in the backend package (`python -m app.datagen.generate`, run by `make data`) instead of `scripts/generate_data.py`. | It will import the hazard and scoring code to check the demo seeds, and stays covered by ruff, mypy and pytest. |
| 2026-10-29 | Every backend start rebuilds the SQLite database from the gold files, so a restart begins a fresh scenario; `make demo-reset` resets a running backend. | Gold data and DB can never drift apart; no migrations in a prototype. |
| 2026-10-29 | The loader also loads `assets_rejected_example.json` at startup as an incoming asset batch, so the Data quality page shows its 2 rejected rows with reasons. Rows that break a contract, duplicate an id or reference an unknown entity are rejected and reported; a missing file or a broken single-object file stops startup. | Makes the contract checks visible in the demo; the plan's loader test still rejects exactly those 2 rows. |
| 2026-10-29 | Forecast tracks are straight lines heading north-north-east at 14 km/h with constant max wind; weakening over land is left to the hazard model's inland decay. | Avoids counting land decay twice; forward speed from the research note. |
| 2026-10-29 | The frontend's pages are chosen by the URL hash (`#/`, `#/audit`, `#/data-quality`; one route table) instead of a router library. | Three static pages don't justify a dependency. |
| 2026-10-29 | Frontend types mirror the API response models, not the gold-file contracts (CODING_STANDARDS F6 reworded). | The frontend only reads API responses; types for files it never sees would be speculative. |
| 2026-10-29 | Rankine decay exponent α = 0.7 instead of the plan's 0.5 (`config/scoring.yaml`). | With 0.5, tropical-storm-force wind reaches ~510 km from a 145 mph storm, so stop-work (P-4.7) would hit PS-14 at advisory 4; 0.7 gives ~240 km (close to the analogue storm's real TS-wind radius) and puts PS-14's arrival at 34 h, 21 h and 8 h for advisories 3–5, as section 8 needs. |
| 2026-10-29 | STG-02's yard sits at 2.3 m so that its P90 flood depth is above zero only from advisory 4 (plan section 2.2). | At 1.4 m it flooded from advisory 1. |
| 2026-10-29 | The ensemble shifts each member's whole track sideways by N(0, cone radius at the landfall lead time); the surge's alongshore distance is measured along the coastline from the member's shifted landfall point. | 2026-10-29 | `GET /exposure?advisory=` serves the stored P50/P90 exposure per asset and staging area (not in the plan's API list). | Feeds the map tooltips now and the explanation and copilot later. |
